# 大喜利けいこ場

`odai.json`（過去の大喜利ファイルから抽出したお題 2,264問 / 回答 18,959件）から
お題をランダムに出題し、自分で回答を書いたあとに「ファイルにあった答え」を見比べる練習アプリ。
仕様は `大喜利アプリ_仕様書.md`。

## 使う

**正式な実装は GitHub Pages で公開している静的ページです。** サーバ不要・iPhone含む
どのブラウザからでも固定URLで開けます。

→ `docs/index.html` を GitHub Pages で公開したURL（リポジトリの Settings → Pages で確認）

- お題データはページ自体に同梱されているので、開けばすぐ遊べる（通信不要）。
- 回答の控えはこの端末のブラウザ（`localStorage`）に保存される。サーバへの送信は無い。
- 回答するまで答えはどこにも描画されない。

## 使い方

- 上部の **出典フィルタ** でお題の出どころを絞る。既定は「茶屋を除く」（茶屋は
  全体の91%を占める短文スタイルのため）。**「✎ 自分でお題を入力」** を選ぶと自前のお題で
  練習できる（既出回答が無いので、答え合わせと⑪事後欄は出ない）。
- **工程フォーム（①〜⑨）** は畳んである。開くと回答作成の工程を順に埋められる。
  全欄が任意で、⑩最終回答さえ書けば送信できる。開閉状態は記憶される。
- 書きかけは自動保存され、リロードしても**同じお題ごと**復元される（iPhoneはタブが
  破棄されやすいため）。次のお題に進むと破棄。
- 回答を書いて **回答する**。押すまでファイルの答えは見えない。
- 書かずに次へ行くなら **パス**。パスしても、そのお題の「ファイルにあった答え」は表示される
  （自分の回答が無いので保存はされない）。パス・回答済みのお題は同じセッション中に再出題されない。
- 回答すると **Claudeに判定してもらう** ボタンが出る。お題・既出回答・自分の回答・理論ファイル
  2本をまとめたプロンプトをクリップボードにコピーし、claude.ai を新しいタブで開く。
  貼り付けて送信するのは自分で行う（Webページから他サイトの認証済みチャットへ自動送信すること
  はできないため）。
- PCブラウザでは `Ctrl/Cmd + Enter` で回答、`→` でパスもできる（タッチ端末では非表示）。

## AIの講評の仕組み

仕様書3章はAPIによる自動採点を想定していたが、APIキーを静的ページに埋め込まず、iPhone単体で
完結させるため、「Claudeのチャットに手渡しする」方式にした。

1. ページ読み込み時、理論ファイル2本（`docs/theory1.txt` / `theory2.txt`）をバックグラウンドで
   取得しておく（クリック時に取得すると、iOS Safariでクリップボード書き込みに必要な
   「ユーザー操作の直後」という条件が切れることがあるため）。
2. 「Claudeに判定してもらう」を押すと、理論2本 + お題 + 既出回答 + 自分の回答 + 出力形式の
   指示を1つのプロンプトに組み立てる。
3. `navigator.clipboard.writeText()` でコピーし、`https://claude.ai/new` を新しいタブで開く。
   クリップボードへの書き込みに失敗した場合は、画面上のテキストエリアを選択状態にするので
   手動でコピーできる。
4. 開いたタブに貼り付けて送信するのは自分で行う。

### 工程フォーム

回答作成の工程を①〜⑪に分けて記録し、講評プロンプトに丸ごと含める。

| | 欄 | 形式 |
|---|---|---|
| ① | 条件 | 形式条件・評価語・時制・視点の4欄 |
| ② | 翻訳 | 「（A）より（B）の方が面白い」の穴埋め＋抽象化チェック |
| ③ | 破壊対象 | 記述 |
| ④ | 第一被り圏 | 着眼3欄固定。埋まっていないと注意を表示 |
| ⑤ | 第二被り圏 | 記述 |
| ⑥ | 空き領域 | 複数欄＋「＋追加」（初期2欄） |
| ⑦ | 軸の選択 | A発見／B実在／C過剰／D言葉／F愚／G情／H毒／I演 から1つ。選ぶと検査質問が出る |
| ⑧ | 発散 | 1案1欄＋「＋追加」（初期5欄）。案数カウンタ＋視点10種のチェック |
| ⑨ | 棄却理由 | 記述 |
| ⑩ | 最終回答 | **必須**。②翻訳のミラー＋整合チェック、仕上げ5点＋E初回性 |
| ⑪ | 事後欄 | 既出回答を見た後に記入。自前お題では非表示 |

**空欄は削除せず `（未記入）` としてプロンプトに含める。** 工程のどこを飛ばしたかが
講評の材料になるため、欄ごと落とすと「飛ばした」のか「欄が無かった」のか区別できない。

E初回性は軸ではなくメタ係数なので、⑦のラジオには入れず⑩に置いている。仕上げチェックは
13項目全部をフォーム化すると記入コストが上がってフォーム自体が使われなくなるため、
5点＋E初回性に圧縮し、残りは講評側で扱う。

#### フォームが止めるようにしたミス

1周使った結果、フォームを素通りしたミスがあったため以下を足した。いずれも**送信は
ブロックしない**（全欄空欄可・最終回答のみで送信可能の原則は維持）。

| 起きたミス | 止め方 |
|---|---|
| ①が1欄で何行にもなり、後から一目で確認できない | 4つの設問に分割 |
| ②翻訳と⑩最終回答の食い違いに気づけない | ⑩に②翻訳をそのまま写し、整合チェックを併置 |
| ②Bに着地の「形式」を書いてしまう | ×○の実例を欄の直下に常時表示 |
| ④を2つで止めて空き領域の見立てが甘くなる | 3欄固定＋不足時に注意を表示 |
| ⑥に案が混入し探索が1本に潰れる | 「具体的な物・人・行動を書いたら、それは案」＋実例を常時表示 |
| ⑧2案で最終回答に進む（飛躍の弱さの主因） | 1案1欄＋案数カウンタ（5案未満は警告色） |
| ⑧の視点が未記入のまま通過 | 視点を常時表示のチェックに。死角になりやすい「制度・運営側」は強調 |
| ⑨で軸を誤解した棄却理由が通過 | 「その軸を捨てた」理由と「その案が弱い」理由を区別させる一行 |

### 講評中の章番号をクリックできるリンクにする

Claudeの講評は「(1-12)」のように理論文書の章番号を引用してくることがある。プロンプトに
「章番号は `docs/theory{1,2}.html#<章番号>` へのMarkdownリンクにする」という指示を入れており、
claude.aiの通常のMarkdown表示でそのままクリック可能なリンクになる。

- `docs/theory1.html` / `theory2.html`（`build_pages.py` が生成）は、各章に `id="1-12"` の
  ようなアンカーを振った閲覧用ページ。目次から手でジャンプすることもできる。
- 理論1は 1-1〜1-13, 3-1〜3-4、理論2は 1-1〜1-7, 2-1〜2-17 という章番号を持つ。**1-1〜1-7 は
  両方の文書に別内容で存在するため曖昧** — プロンプト側で「この範囲は必ずどちらの文書か
  明記させる」よう指示している。
- 元のスクレイプデータに残っていた `note.com` のURLとページ番号（ページ送りのノイズ）は
  生成時に自動で除去される。

## お題データの再生成・ページの作り直し

元ファイルを更新したら:

```
python extract_odai.py <お題ファイルのあるフォルダ> -o odai.json
python build_pages.py
```

1つ目で `odai.json` を再生成し（`ハシリドコロ_大喜利理論_1 / _2` は自動で除外される）、
2つ目で `docs/index.html`（GitHub Pages が配信する実体）を作り直す。
`docs/index.html` は生成物なので、手で直接編集せず `page.tpl.html` を編集して
`build_pages.py` を再実行すること。

## 構成

| ファイル | 中身 |
|---|---|
| `docs/index.html` | **GitHub Pages が配信する本体**（`page.tpl.html` + `odai.json` から生成） |
| `page.tpl.html` | `docs/index.html` の元になるテンプレート |
| `build_pages.py` | `page.tpl.html` + `odai.json` → `docs/index.html` を生成するスクリプト |
| `odai.json` | 抽出済みお題データ |
| `extract_odai.py` | `odai.json` の生成スクリプト |
| `ハシリドコロ_大喜利理論_1.txt` / `_2.txt` | 講評の評価軸に使う理論文書（リポジトリ側の原本） |
| `docs/theory1.txt` / `theory2.txt` | 上記のコピー（`build_pages.py` が生成。Claudeに渡すプロンプト用に fetch() される） |
| `docs/theory1.html` / `theory2.html` | 章にアンカーを振った閲覧用ページ（`build_pages.py` が生成。講評中の章番号リンクの飛び先） |

### 参考: ローカルFlask版（任意）

デスクトップでサーバを立てて動かしたい場合向けに、同等機能の Flask 版も残してある
（`app.py` + `templates/index.html`）。回答ログは `history.jsonl` に追記される。
iPhone単体で使う分には不要 — 上記の GitHub Pages 版だけで完結する。

```
pip install -r requirements.txt
python app.py     # → http://localhost:5000
```

| エンドポイント | 中身 |
|---|---|
| `GET /api/odai?exclude=茶屋` | ランダムなお題1問（`answers` は返さない） |
| `GET /api/odai/<id>/answers` | そのお題の答え |
| `POST /api/history` | `{odai_id, answer}` を `history.jsonl` に追記 |
| `GET /api/sources` | 出典一覧（件数付き） |
| `POST /api/reset` | 出題済みの記録をクリア |

## 直した不具合

- **お題と関係ない断片が「答え」として混ざる**（2024/08/28）。`extract_odai.py` に、
  `【画像】`や`【2回戦】`のような4文字未満の区切り見出しが `continue` されずに素通りし、
  前のお題の回答として誤って追加されるバグがあった（2,266問中78件が該当）。
  `odai.json` から該当データを除去し、抽出スクリプトと `build_pages.py` の両方に
  再発防止のフィルタを入れた。
